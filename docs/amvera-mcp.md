# Размещение в Amvera через MCP

Выбран пользователем способ 3: управление размещением через MCP Amvera.
MCP пока не подключён к этому чату; проверенного размещения нет.

## Что нужно сейчас

1. Создать аккаунт Amvera и получить MCP access token в личном кабинете.
2. Подключить удалённый MCP-сервер к Codex. Выбрать один регион:
   - Москва: `https://openmcp.msk0.amvera.ru/mcp`
   - Варшава: `https://openmcp.waw0.amvera.ru/mcp`
3. Аутентификация — HTTP-заголовок `Authorization: Bearer <access_token>`.
   MCP-токен не является токеном Telegram-бота. Оба токена держать вне переписки
   и репозитория.

## Codex: конфигурация без токена в файле

В пользовательский `~/.codex/config.toml` добавить блок, сохранив существующие
настройки. Это пример для Москвы; для Варшавы заменить только URL.

```toml
[mcp_servers.amvera]
url = "https://openmcp.msk0.amvera.ru/mcp"
bearer_token_env_var = "AMVERA_MCP_TOKEN"
```

В окружении процесса, который запускает Codex, должна быть переменная
`AMVERA_MCP_TOKEN` со значением токена Amvera. Не добавлять префикс `Bearer`:
Codex добавит его сам. Запись в `.env` Python-приложения сама по себе не
передаёт переменную окружения MCP-клиенту.

Альтернативная команда добавления того же блока:

```powershell
codex mcp add amvera --url https://openmcp.msk0.amvera.ru/mcp --bearer-token-env-var AMVERA_MCP_TOKEN
```

В расширении IDE доступно: настройки Codex → MCP servers → Add server →
Streamable HTTP. Для Bearer-токена использовать конфигурацию выше.
После изменения окружения полностью перезапустить приложение, чтобы оно
получило новую переменную. В IDE после изменения конфигурации перезапустить
расширение. В CLI проверить `codex mcp list`.

Локальная настройка Codex не гарантирует появления MCP в размещённом ChatGPT
Work: там используются подключённые плагины. В каталоге, доступном в текущем
сеансе, плагин Amvera не найден. Если инструменты не появятся после настройки,
продолжить в Codex CLI/расширении с этой же папкой проекта. Подключение считается
проверенным только после успешного чтения списка проектов через MCP.

Не вводить MCP-токен в обычное сообщение, не вставлять его в отслеживаемый
`config.toml` проекта. Кодекс в данной среде не менял пользовательские настройки:
для подключения нужно локально настроить секрет и перезапустить MCP-клиент.

## Тариф

Amvera предоставляет стартовый баланс для тестирования. Постоянного бесплатного
размещения в опубликованных тарифах нет. На 17 ноября 2026 года указаны:
«Пробный» — 170 ₽/30 дней, «Начальный» — 290 ₽/30 дней.
Ресурсов минимального тарифа может не хватить: размер памяти проверяется
при реальной сборке. Это не предложение автоматически выбрать платный тариф.
До запуска проекта необходимо зафиксировать конкретный тариф и расходы.

## Схема приложения

- Один экземпляр приложения, Python 3.13 и aiogram, long polling.
- SQLite: `DATABASE_URL=sqlite:////data/poker.db`.
- В `amvera.yml` постоянное хранилище монтируется в `/data`.
- В каталоге кода и Artifacts рабочую базу не хранить.
- `BOT_TOKEN` задаётся как секрет в Amvera; MCP-токен нужен клиенту Codex,
  не процессу Telegram-бота.
- Перед запуском применяются миграции. Домен и webhook не нужны.
- При переключении с webhook он отключается с сохранением ожидающих updates.
- Перед публикацией через MCP загружаются только файлы приложения:
  без `.env`, `.tools`, `.venv`, локальных баз, кэшей и конфигурации MCP.

Точка входа и конфигурация подготовлены для текущего первого этапа. Учёт игр
и виджеты ещё разрабатываются. Реальная сборка, запуск и постоянство диска
проверяются после подключения MCP и настройки секрета Telegram.

## Проверка размещения

1. Прочитать список проектов через MCP и выбрать точный проект.
2. Уточнить тариф; настроить секреты и постоянный диск.
3. Загрузить пакет приложения, запустить сборку и проверить логи без вывода токенов.
4. Проверить `/start`, создание клуба и приглашение друга в Telegram.
5. Перезапустить приложение и убедиться, что клуб и шаги ввода сохранились.
6. Проверить ответ бота при выключенном компьютере владельца.
